# Product direction for the next release

The working product hypothesis is a desktop monitoring station for a small organization responsible for several locations. This is a prioritization choice for the pilot, not validated market demand.

The primary workflow is: identify the location and hazard, read official instructions, confirm source freshness and monitoring state, acknowledge the alert, and review notification outcomes. Grouped locations and incident evidence support shift handoffs. Optional repeater and specialist marine tools remain available without dominating the default view.

The initial release should be evaluated on warning visibility during partial outages, absence of false all-clear states, correct per-channel recovery, time to first configured location, time to identify the protective action, and acknowledgment completion. Local metrics record alert-check duration, first detection delay, source failures, duplicate/rule suppression, delivery outcomes, speech failures, and setup completion. These measurements describe this installation; they are not service-level guarantees or company-wide analytics.

Use pilot-validation.md to recruit representative operators and record actual outcomes. Resolve consequential reliability and usability issues before broad rollout. Defer pricing, channel expansion, and native feature-parity commitments until the pilot establishes which workflows customers need.
